# Киоск «Максима» — дизайн

Дата: 2026-11-16. Статус: черновик, на согласовании.

## Зачем

В холле стоматологического центра «Максима» (Смоленск, ул. Исаковского, 24) стоит сенсорный инфокиоск (~40"). Старый сайт `kiosk.maxima-sm.ru` — копия десктопного Bitrix-сайта (шаблон Aspro Medc2) — сейчас не открывается: PHP-ошибка `ArgumentCountError` в шаблоне. Под палец он и не был сделан.

Новый сайт решает три задачи:

1. **Комплаенс.** Закрыть требования юристов к «информационному стенду»: 28 пунктов (ПП РФ № 659 от 30.05.2026 о платных медуслугах, ЗоЗПП, 323-ФЗ). Источник — `docs/legal/requirements-stand.doc` (оригинал юристов, колонки «стенд»/«сайт» по каждому пункту). Разработчик переносит таблицу в `src/legal/requirements.ts` — канонический список для `check-content`; «стенд: −/пусто» → «неприменим к киоску» (только п. 26); п. 27 — условный (баннер приостановки).
2. **Приветствие.** Приятный «велком»-экран клиники: кто мы, часы работы, врачи, цены.
3. **Игра для детей.** Понятная крупная кнопка, ведущая в игру «Планета Зуб» (отдельный проект, детская стоматология «Планетарий»).

Успех: проверяющий на стенде за пару касаний находит любой из 28 пунктов; пациент в очереди без инструкции понимает, куда нажать; ребёнок сам попадает в игру и киоск сам возвращается в исходное состояние.

## Цели / не-цели / анти-цели

**Цели**
- Все пункты требований, помеченные «стенд», доступны на киоске.
- Touch-first: крупные цели, никакого hover, никакой клавиатуры.
- Данные отделены от вёрстки (JSON + PDF), чтобы позже подключить общую систему правки данных без переписывания интерфейса.
- Киоск сам возвращается на главную после простоя; работает при кратком пропадании сети.

**Не-цели (v1)**
- Админка / CMS. Данные редко, правит разработчик (владелец проекта). CMS — следующий этап.
- Онлайн-запись, формы, любые поля ввода.
- Перенос блога, акций, примеров работ, отзывов с основного сайта.
- Мультиклиника (Планетарий, другие клиники сети) — только «Максима».
- Правки самой игры «Планета Зуб» (см. «Зависимости»).

**Анти-цели (провал, даже если «работает»)**
- Посетитель уходит с киоска на внешний сайт и не может вернуться.
- Сайт собирает ПДн / ставит аналитику и тем самым создаёт новые обязательства (баннер куки, политика).
- Юридический пункт «тихо» пустой: заглушка, которую нельзя отличить от настоящего документа.
- Главная перегружена мелким текстом, как десктопный сайт.

## Ограничения

- Устройство: сенсорный киоск ~40", браузер в kiosk-режиме (Chrome/Chromium, постоянный профиль). ОС — Windows, доступ к машине у владельца есть (стартовый URL и флаги Chrome настраиваем сами). Ориентация — **ландшафт 1920×1080** (подтверждено владельцем): главная обязана помещаться в один экран без прокрутки. Портрет поддерживается как запасной вариант.
- Внешние ссылки нельзя открывать в киоске (выход из сайта без возврата).
- Игра «Планета Зуб» отдаёт `X-Frame-Options: DENY` → встроить в iframe нельзя, только переход в той же вкладке.
- Книга жалоб (п. 19) — только оригинал на бумаге; на киоске — указание, где она.
- Бренд: шрифт Mulish, акцент `#788BFF` / `#5465FF`, тёмный текст `#222`, фон `#F5F5F5` (сняты с maxima-sm.ru). Логотип «МАКСИМА» с цветными точками — исходник получить у клиники.

## Подходы

| | Подход | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| A | React + Vite SPA, данные из `data/*.json` во время работы | Обновление = замена файла, без пересборки; будущая CMS отдаёт тот же JSON по API; знакомый стек | Бандл тяжелее чистой статики | **Выбран** |
| B | Astro, статическая генерация | Самый лёгкий результат | Любая правка = пересборка; CMS только через вебхук на ребилд | Отклонён |
| C | Починить Bitrix-киоск | Контент частично есть | Десктопная вёрстка, несовместимость шаблона с PHP, чинить дороже, чем писать | Отклонён |

Выбор сделал владелец проекта (вариант A).

## Решено

### Стек
- React 18 + TypeScript + Vite. Без UI-кита: крупные киоск-плитки проще на своих CSS-модулях / CSS-переменных с токенами бренда (решение разработчика).
- Роутинг: `react-router` (hash-роутер, чтобы статика работала без настройки сервера).
- PDF: `pdfjs-dist`, свой просмотрщик.
- QR: генерация на клиенте (`qrcode`).
- Офлайн: service worker (`vite-plugin-pwa` / Workbox) — кэшируются приложение, `data/*.json`, PDF.
- Тесты: Vitest + Testing Library, поведенческие (данные → экран, простой → главная, внешняя ссылка → QR, валидатор контента).
- Деплой: VPS Reg.ru `80.78.253.231` (там же patient-anketa / `anketa.maxima-sm.ru`, profosmotr, teampulse, aquarius, implant). Поддомен `kiosk.339933.net` (решение владельца), A-запись в DNS Reg.ru → 80.78.253.231 (там же `anketa.339933.net`, `team.339933.net`). Статику (`dist/`) отдаёт системный nginx напрямую, без своего контейнера и порта; HTTPS через certbot. Выкладка — rsync `dist/` в `/opt/maxima-kiosk/`. Старый `kiosk.maxima-sm.ru` (91.106.207.66, Bitrix) не трогаем.

### Модель данных (`public/data/`)
Схемы описаны в TypeScript + валидатор (zod), сам JSON — источник правды.

- `clinic.json` — наименование, юр. адрес (строго по ЕГРЮЛ), адреса деятельности с режимом работы (по лицензии), ОГРН, ИНН/КПП, email, сайт, телефоны, почтовый адрес для обращений, главный врач (ФИО, телефон, график приёма), режим помещения для ознакомления с меддокументацией, лицензия (номер, дата, орган, срок, PDF), блок `suspension` (активно/даты/текст) для п. 27, `gameUrl`.
- `doctors.json` — ФИО, специальность по сертификату, фото (опц.), диплом, постдипломное образование, сертификат, повышение квалификации, аккредитация (поля по п. 15), график работы по дням со сменностью.
- `documents.json` — разделы и элементы; тип элемента: `pdf` (файл в `public/docs/`), `link` (внешний URL → QR), `text` (короткий текст, напр. «Сроки ожидания платных услуг указаны в договоре»), `notice` (напр. «Книга жалоб — у администратора»). У каждого элемента — `legalRef` (номера пунктов требований, которые он закрывает).
- `authorities.json` — Минздрав Смоленской обл., ТО Росздравнадзора, ТО Роспотребнадзора: название, адрес, телефон.
- `prices` — прайс как PDF (утверждённый, с подписями — п. 11), без парсинга в таблицу в v1.

### Экраны
1. **Главная.** Логотип, «Добро пожаловать», сегодняшний режим работы, 5–6 больших плиток: «Документы и сведения», «Врачи и расписание», «Цены», «Права пациента и обращения», «Контакты», «Игра для детей 🚀» (выделена цветом). Если `suspension.active` — баннер сверху на всех экранах.
2. **Документы и сведения** — разделы:
   - Об организации: реквизиты (п. 1–7), выписка ЕГРЮЛ (9), лицензия (10), устав (21).
   - Услуги: прайс (11), образцы договоров (17), сроки ожидания платных (14), сроки бесплатной помощи + территориальная программа (12).
   - Стандарты и клинические рекомендации (8, 13): pravo.gov.ru, рубрикатор Минздрава, СтАР — всё QR.
   - Нормативные акты: ПП № 659 (18), ЗоЗПП, 323-ФЗ (20).
3. **Врачи и расписание** (15, 16) — список карточек → карточка врача с квалификацией таблицей и графиком.
4. **Права пациента и обращения** — правила поведения (25), книга жалоб (19), как подать обращение/жалобу (28), почтовый адрес и email (22), главный врач и помещение для ознакомления с меддокументацией (23), надзорные органы (24).
5. **Контакты** — адрес, телефоны, режим, email, сайт (QR).
6. **Просмотрщик PDF** — на весь экран, листание кнопками и свайпом, зум кнопками +/−, крупная кнопка «Назад».
7. **QR-модал** — для любой внешней ссылки: заголовок, QR, читаемый URL, «Наведите камеру телефона».

### Поведение киоска
- Простой 90 с → главная, закрыты все модалки/PDF.
- Отключены: выделение текста, контекстное меню, pinch-zoom страницы (зум только внутри PDF), overscroll-навигация.
- Минимальная цель касания 72×72 px, базовый шрифт ≥ 24 px (рассчёт на 40" с ~1 м).
- Без аналитики, cookies, форм — сайт не обрабатывает ПДн (п. 26 «только сайт» к киоску не применяется).
- Кнопка «Игра для детей» → `location.href = gameUrl` в той же вкладке.

### Контроль полноты
Скрипт `npm run check-content`: валидирует JSON по схемам, проверяет наличие PDF и печатает таблицу 28 пунктов: закрыт / не закрыт / неприменим к стенду. Незакрытый пункт на киоске не показывается заглушкой — элемент просто отсутствует, а скрипт показывает дыру разработчику.

## Зависимости

- **Игра «Планета Зуб»** не задеплоена (пакет `planeta-zub-deploy.zip`, вход по паролю + cookie, свой домен). Её собственные таймауты возвращают на заставку игры, не на киоск. Нужна отдельная доработка игры: кнопка «← на стенд» + возврат на киоск по простою (вместо своей заставки), адрес киоска — из конфига игры. **Решение (разработчика):** плитка игры показывается только если в `clinic.json` задан `gameUrl`; задаём его лишь после того, как игра задеплоена с возвратом на стенд и пароль введён на самом киоске. До этого плитки нет — киоск не уходит в тупик.
- **Контент** (сканы, реквизиты, данные врачей, прайс) — от клиники. Код строится на примерных данных, помеченных как демо.
