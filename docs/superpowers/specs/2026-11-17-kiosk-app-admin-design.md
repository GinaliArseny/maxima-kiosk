# Киоск «Максима», этап 2: программа-киоск, заставка, админка — дизайн

Дата: 2026-11-17. Статус: утверждён владельцем 2026-11-17. Продолжение `2026-11-16-maxima-kiosk-design.md` (сайт-стенд v1 уже работает на `https://kiosk.339933.net`).

## Зачем

Сайт-стенд v1 открыт в Chrome на сенсорном Windows-компьютере в холле. Три проблемы:

1. **Браузер легко закрыть.** Посетитель (или ребёнок) выходит на рабочий стол — киоск мёртв до прихода админа.
2. **Простаивающий экран пустой.** Хочется заставку — видео клиники по кругу. Видео уже лежат в Jellyfin в локальной сети.
3. **Данные правит только разработчик.** Прайсы, документы, врачи меняются через разработчика (правка JSON + деплой). Нужно, чтобы правил админ клиники сам.

Успех: посетитель не может выйти из киоска; после нескольких минут простоя крутится видео из плейлиста Jellyfin, касание возвращает на главную; админ клиники со своего компьютера меняет прайс/врача/документ, и через минуту-две это на киоске — без разработчика и без похода к киоску.

## Цели / не-цели / анти-цели

**Цели**
- Exe для Windows: открывается — сразу на весь экран, закрыть нельзя без PIN.
- Заставка из плейлиста Jellyfin по простою, по кругу.
- Веб-админка на сервере для админа клиники: врачи, документы, прайс, сведения о клинике, настройки заставки. Сохранил — опубликовано.

**Не-цели**
- Черновики, согласование, роли «редактор/утверждающий» — решение владельца: админ публикует сразу.
- Система данных для других сайтов/клиник — решение владельца: только этот киоск.
- Правка интерфейсных текстов киоска (приветствие, названия плиток) из админки.
- Автообновление exe, удалённое управление компьютером киоска, несколько киосков.
- Загрузка видео в Jellyfin через админку (видео ведут в самом Jellyfin).

**Анти-цели (провал, даже если «работает»)**
- Админ сохранил кривые данные — киоск показывает ошибку или пустоту.
- Выкладка новой версии сайта затирает правки админа.
- Ключ Jellyfin или пароль админки оказываются в публичных файлах `kiosk.339933.net`.
- Касание по заставке «проваливается» и открывает плитку под ней.
- Пациент видит рабочий стол Windows, панель задач или окно ошибки.

## Ограничения и факты

- Компьютер киоска: Windows, редакция любая и может смениться, сенсорный экран 1920×1080 ландшафт, **физической клавиатуры нет**, только экранная. Доступ к машине у владельца полный.
- Jellyfin — **отдельный сервер в локальной сети клиники** (не на киоске), тот же сервер опубликован наружу как `videocrab.ru`.
- Сайт киоска — HTTPS (`kiosk.339933.net`), Jellyfin в сети — скорее всего HTTP. Браузер блокирует HTTP-видео на HTTPS-странице (mixed content) → заставку показывает программа, а не сайт.
- Игра (`emailer.339933.net/game/`) — вход по паролю + cookie, `X-Frame-Options: DENY`; переход в том же окне, возврат на стенд уже реализован в игре.
- VPS Reg.ru `80.78.253.231`: сайт отдаёт системный nginx из `/opt/maxima-kiosk/dist`. Сейчас `public/data`, `public/docs`, `public/doctors` входят в `dist/` и выкладываются rsync'ом из репо.
- Админ правит со своего компьютера через браузер, не на киоске (решение владельца).

## Подходы

### Программа-киоск

| | Подход | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| A | Electron-обёртка над `kiosk.339933.net` + настройка Windows | Один exe; полный контроль окна, навигации, выхода по PIN; заставка внутри; Chromium с кодеками H.264/AAC | Exe ~100 МБ; Windows-уровень всё равно настраивать | **Выбран** |
| B | Chrome `--kiosk` + сторож-перезапуск | Ничего писать не надо | Выход по паролю невозможен; заставку из HTTP-Jellyfin на HTTPS-странице не показать | Отклонён |
| C | Готовый киоск-браузер (OpenKiosk, SiteKiosk) | Готовый выход по паролю | Заставку из плейлиста Jellyfin нормально не встроить; SiteKiosk платный | Отклонён |

### Правка данных

| | Подход | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| A | Directus (готовая headless CMS) | Готовые формы, роли, история | Избыточно для одного киоска; ещё один тяжёлый сервис; свои проверки всё равно писать | Отклонён (система только для киоска) |
| B | Своя мини-админка, пишет те же `data/*.json` | Точно под данные киоска; та же zod-схема, что у киоска; панель требований юристов | Писать и поддерживать | **Выбран** |
| C | Google-таблица / папка Яндекс Диска + синхронизация | Ноль обучения | Ошибки видны только после публикации; длинные тексты квалификаций в ячейках; PDF отдельно | Отклонён |

## Решено

### Репозиторий

Всё в репо `maxima-kiosk` (монорепо): существующий сайт — как есть; `app/` — Electron-программа; `admin/` — сервер и веб-интерфейс админки. Схемы данных (`src/data/schema.ts`) и требования/покрытие (`src/legal/*`) — общие для сайта и админки, не дублируются.

### 1. Программа-киоск (Electron)

**Окно и навигация**
- Одно окно: `kiosk: true`, на весь экран, без рамки и меню, поверх всех окон. Грузит `https://kiosk.339933.net/`.
- Переходы разрешены только на `kiosk.339933.net` и `emailer.339933.net` (игра). Любой другой переход и любые новые окна — блокируются (сайт и так показывает внешние ссылки только QR-кодом).
- Постоянный профиль (persistent session) — cookie игры переживает перезапуск; пароль игры вводится один раз.
- Отключены: DevTools, зум страницы, контекстное меню, перетаскивание файлов в окно, `Alt+F4`/`Ctrl+W`/`F11`/`Ctrl+R` и прочие сочетания (на случай подключённой клавиатуры или экранной клавиатуры с Alt).
- Нет сети при старте — своя заставка «Подключаемся…» с повтором; после первой загрузки сайт сам работает офлайн (service worker v1).
- Экран не гаснет (блокировка энергосбережения из программы + настройка питания Windows).

**Выход по PIN**
- Скрытый жест: 5 касаний в левый верхний угол (зона ~100×100 px) за 3 секунды → поверх всего свой PIN-пад (кнопки 0–9 на экране, без системной клавиатуры).
- PIN верный → сервисное меню: «Перезапустить киоск», «Выйти на рабочий стол», «Выключить компьютер». Неверный — PIN-пад закрывается; после 5 ошибок подряд — блокировка жеста на 5 минут.
- PIN хранится хэшем в локальном конфиге на компьютере киоска (не на сервере). Смена PIN — в том же сервисном меню.

**Защита на уровне Windows** (программа сама этого не перекрывает: `Ctrl+Alt+Del`, клавиша Win, свайпы от краёв экрана обрабатывает Windows)
- Отдельная локальная учётка «Киоск» без прав администратора, автовход.
- Для этой учётки вместо рабочего стола (shell) запускается программа-киоск. «Выйти на рабочий стол» из сервисного меню запускает Проводник.
- Политики для учётки: выключены свайпы от краёв экрана, диспетчер задач, блокировка/смена пользователя/смена пароля в `Ctrl+Alt+Del`, уведомления.
- Сторож: программа упала или окно сайта упало — в течение ~10 с снова на экране главная. Намеренный выход по PIN сторож не перебивает.
- **Любая редакция Windows 10/11 (Home, Pro, Enterprise), переживает обновления** (требование владельца). Поэтому только механизмы, которые есть во всех редакциях: замена shell для одной учётки через её ветку реестра, политики через реестр, автовход через реестр. Никаких Assigned Access / Shell Launcher / Keyboard Filter (только Enterprise/Education) и gpedit.
- Программа не полагается на то, что настройка Windows сработала: окно само возвращается поверх и в фокус, если его что-то перекрыло (свайп открыл панель Windows, всплыло окно). Настройка Windows — второй слой, не единственный.
- Самопроверка: при старте программа смотрит, какие защиты Windows реально действуют (shell, свайпы, диспетчер задач), и показывает это в сервисном меню. Если крупное обновление Windows что-то сбросило, это видно, и достаточно запустить скрипт установки повторно (скрипт можно запускать сколько угодно раз).
- Всё это — PowerShell-скрипт установки + пошаговая инструкция в `deploy/kiosk-setup.md` (заменяет текущую инструкцию про ярлык Chrome).
- **Путь назад** (решение разработчика): скрипт отката (вернуть Проводник как shell, снять политики) и обязательная отдельная учётка администратора Windows, которую скрипт не трогает. Ошибка настройки не должна оставлять киоск неуправляемым.

**Ввод текста** (решение разработчика)
- Посетителям печатать нечего: игра спрашивает только пароль доступа (вводит владелец, cookie живёт 400 дней), полей ввода на сайте нет.
- Владельцу печатать нужно при установке и обслуживании: адрес и ключ Jellyfin, первый PIN, пароль игры. Это делается с USB-клавиатурой или через удалённый доступ — своей экранной клавиатуры в программе нет.
- В сервисном меню — пункт «Войти в игру заново» (открывает форму пароля игры) на случай, если cookie игры сбросят.
- Профиль программы новый: cookie игры из Chrome не переносится, пароль игры вводится один раз при установке программы.

**Установка** — установщик `.exe` (NSIS). Обновление программы — вручную, редко (сайт обновляется с сервера без переустановки).

### 2. Заставка из Jellyfin

- Живёт в программе, отдельным окном поверх сайта (не в сайте): из-за mixed content и чтобы ключ Jellyfin не попал в публичные файлы.
- **Простой** определяется по всей системе (время с последнего касания), порог — из настроек (по умолчанию 3 мин). Сайт под заставкой сам вернётся на главную (его 90 с срабатывают раньше).
- **Касание по заставке** закрывает её и не передаётся сайту (окно заставки перехватывает касание целиком). Под ней уже главная.
- **Что играет**: элементы плейлиста (или папки/коллекции) Jellyfin по порядку, по кругу; новый ролик в плейлисте подхватывается при следующем запуске заставки. Без звука по умолчанию (переключатель в админке).
- Ролик в формате, который Chromium не играет напрямую, — запрашивается у Jellyfin в перекодированном виде (H.264). Ролик не открылся — пропустить, следующий.
- Jellyfin недоступен или плейлист пуст — заставка не включается, остаётся главная; попытка при следующем простое.
- Заставка включилась, пока в окне открыта игра, — окно сайта уходит на главную киоска (после касания посетитель видит стенд, не брошенную игру). Решение разработчика.
- **Что известно о Jellyfin клиники** (проверено 2026-11-17): сервер «VideoCrab», Jellyfin 12.0.0, в сети `http://192.168.100.100:8096`, снаружи тот же сервер — `https://videocrab.ru` (одинаковый ID сервера). Образцы видео — mp4, H.264 + AAC (Chromium играет без перекодирования); есть горизонтальные 1920×1080 (4 мин / 643 МБ, 36 мин / 5 ГБ) и вертикальное 608×1080.
- **Какие ссылки принимает админка**: ссылка из веб-интерфейса Jellyfin (`…/web/#/details?id=…`) и ссылка на скачивание (`…/Items/<id>/Download?ApiKey=…`), с внутренним адресом или с `videocrab.ru`. Из ссылки берётся только ID элемента; ключ из ссылки отбрасывается и в публичный файл не попадает. Элемент — отдельное видео, плейлист или папка (раскрывается в список видео). Можно добавить несколько ссылок — играют по порядку.
- **Рекомендуемый способ** — один плейлист «Заставка киоска» в Jellyfin: ссылка в админке вставляется один раз, дальше ролики добавляют/убирают в самом Jellyfin, админку не трогают. Плейлист должен быть доступен пользователю «kiosk» (общий доступ к плейлисту в Jellyfin). Рядом с полем ссылки в админке — короткая инструкция «как достать ссылку» со скриншотом. Ссылки с `ApiKey` в инструкции не используются.
- **Откуда играет киоск**: сначала внутренний адрес (быстро, без интернета), если недоступен — внешний `videocrab.ru`. Видео стримится по сети, не скачивается целиком (файлы до 5 ГБ).
- **Доступ к Jellyfin**: ключ API в Jellyfin даёт полные права администратора сервера, поэтому на киоске его не держим. Для киоска заводится отдельный пользователь Jellyfin «kiosk» с доступом только к библиотеке заставки; программа входит под ним (логин + пароль в локальном конфиге) и получает свой токен.
- **Вертикальное видео** на горизонтальном экране: по центру целиком, по бокам — размытая растянутая копия того же кадра вместо чёрных полос. Решение разработчика.
- **Настройки делятся на два места:**
  - на сервере (правит админ, публичный файл `data/screensaver.json`): вкл/выкл, порог простоя в минутах, плейлист (админ вставляет ссылку на плейлист из веб-интерфейса Jellyfin — сохраняется ID), звук вкл/выкл;
  - на компьютере киоска (локальный конфиг, не публичный): внутренний и внешний адрес Jellyfin, логин и пароль пользователя «kiosk».
- Админка проверяет при сохранении формат ссылки; доступность видео не проверяет (решение разработчика: киоск сам пропускает то, что не открылось).

### 3. Админка

**Где и как**
- `https://kiosk-admin.339933.net` (новая A-запись → `80.78.253.231`, HTTPS через certbot), тот же VPS.
- Сервер: Node.js + TypeScript. Веб-интерфейс: React + TypeScript (как сайт), формы под мышь/клавиатуру обычного компьютера. Сервис работает постоянно, nginx проксирует.
- Вход: логин + пароль. Учётки — админ клиники и владелец; создаются командой на сервере, регистрации нет. Сессия в httpOnly-cookie, ограничение попыток входа. В индекс поисковиков не попадает.

**Хранение данных (важно)**
- Данные переезжают из сборки в отдельный каталог на сервере: `/opt/maxima-kiosk/content/{data,docs,doctors}`. nginx отдаёт `/data/`, `/docs/`, `/doctors/` оттуда.
- Выкладка сайта (`rsync dist/`) эти каталоги больше не трогает → правки админа не затираются. `public/data` и т.п. в репо остаются как стартовое наполнение (один раз копируются в `content/`) и как данные для разработки.
- Источник правды после запуска админки — сервер, не репо.

**Что редактируется**
- **Врачи**: добавить / скрыть / удалить / порядок; ФИО, специальность, фото (загрузка jpg/png → сервер сам делает webp), квалификация — список строк «вид документа + сведения», график по дням недели.
- **Документы**: 5 разделов киоска (Об организации, Услуги, Стандарты, Нормативные акты, Права пациента) фиксированы; внутри — добавить / заменить / удалить / порядок элементов: PDF (загрузка), ссылка (будет QR), текст, объявление. Для каждого элемента — какие пункты требований юристов он закрывает (выбор из списка с человеческими названиями пунктов; у существующих — сохраняются).
- **Цены**: отдельный экран — «загрузить новый прайс (PDF)»; старый заменяется на киоске.
- **Клиника**: реквизиты, адрес, телефон, email, сайт, режим работы по дням, главный врач, лицензия, ссылка на игру, приостановка работы (вкл, с/по, текст).
- **Надзорные органы**: название, адрес, телефон, сайт.
- **Заставка**: см. выше.

**Сохранение = публикация**
- Каждое сохранение проверяется той же zod-схемой, что у киоска, плюс связи (PDF на месте, прайс указан и существует). Ошибка → не сохраняется, админ видит, что именно не так, по-русски, на поле формы.
- Запись атомарная (временный файл + переименование): киоск никогда не видит полузаписанный JSON.
- Загруженные PDF/фото получают новое уникальное имя; старые файлы не удаляются сразу (на них ссылается история).
- Ограничения загрузки: PDF до 30 МБ и действительно PDF; фото до 10 МБ.

- «Скрыть врача» — новый необязательный флаг `hidden` в схеме врача; киоск скрытых не показывает. Решение разработчика.
- Двое правят одновременно: сохранение несёт версию, с которой открыта форма; если файл уже изменён другим — отказ «данные изменились, обновите страницу». Решение разработчика.

**История и откат**
- Каждое сохранение кладёт снимок всех JSON в историю: кто, когда, какой раздел. Экран «История»: список, «вернуть эту версию» (тоже сохранение, тоже в историю).
- Ежедневный архив `content/` на сервере, хранится 30 дней. Решение разработчика.

**Панель требований юристов**
- На главной админки: сколько из 28 пунктов закрыто, список незакрытых человеческими словами («п. 16 — графики работы врачей») — тот же расчёт, что `check-content`.

**Как быстро доезжает до киоска**
- Сервер при каждом сохранении обновляет `data/version.json`. Сайт киоска раз в минуту проверяет его; если поменялся — перезагружается при ближайшем простое (никто не трогает 90 с / открыта главная). Итого 1–3 минуты вместо нынешних ~30. Таймер 30 минут остаётся как запасной.
- Service worker сайта перестаёт заранее кэшировать фото врачей сборки (они теперь меняются без пересборки) — кэширует при показе.

## Открыто (уточнить у владельца до плана)

- Есть ли удалённый доступ к компьютеру киоска (AnyDesk / RDP / другой) или тестовая Windows-машина — от этого зависит, проверяет ли разработчик блокировку Windows сам или пишет пошаговый чек-лист владельцу «вслепую».

## Оставлено разработчику

Структура компонентов и экранов админки; библиотеки сервера (HTTP-фреймворк, хранение сессий, обработка изображений); формат файлов истории и сколько хранить; механизм сторожа (служба / планировщик / внутренний перезапуск); конкретные API-вызовы Jellyfin и параметры перекодирования; Docker или systemd для админки (по примеру соседей на VPS); вид PIN-пада и сервисного меню; тесты (в стиле существующих: поведенческие, моки только на границах — Jellyfin, файловая система не мокается).
